# Baron's Journal UI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the PySide6 desktop UI: a full-screen window that follows Barony's save, shows the run's stats, keeps notes per run and per floor (secret levels included), and has the floor, alchemy and scroll references, in two switchable layouts.

**Architecture:** First, a small extension to `data` and `journal` so floors are keyed by `(dungeon_lvl, secret)`. Then a `ui` package:
- one `SessionController(QObject)` owns the `Journal`, the save watching, the follow mode, and the live/past view state, and publishes an immutable `ViewState` and a `Banner` through signals
- self-contained panel widgets render from `ViewState`
- a `LayoutManager` moves the same panel instances between two `QSplitter` arrangements

Everything runs on the main thread.

**Tech Stack:** Python 3.13, PySide6 6.12, SQLite (stdlib), pytest + pytest-qt, uv.

**Spec:** `docs/superpowers/specs/2026-11-13-ui-design.md`. Executors read the spec and `docs/data-layer.md` alongside this plan.

## Global Constraints

- `data`, `reference` and `journal` must not import Qt. UI code lives only in `src/barons_journal/ui/`.
- The UI uses only the typed objects from those packages. It never reads raw save JSON or queries SQLite directly.
- **Never reveal unidentified items:** display `Item.name` only. Never display, tooltip, sort or group by `item.type` / `item.appearance`, or a name looked up from `type`, for an item with `identified == False`. Blessing/curse is shown only when `identified`.
- Call `journal.record_run(save)` on every successful load, before any other journal call for that run.
- Every stats view carries the snapshot caption ("As of floor N, saved HH:MM").
- Filter out effects with `hidden == True`.
- On `InvalidSaveError`, keep the last good data on screen and show the message.
- All `Journal` calls happen on the main thread. No worker threads.
- Never write to game files.
- Timings: save-change debounce **300 ms**, retry **5 times, about 1 s apart**, note autosave after **600 ms** idle.
- Default layout **C ("focus")**. First launch opens maximised.
- Past runs are **read-only** (notes and scrolls). An *ended* live run stays **editable**.
- Tests never touch the real journal, the real QSettings, or `~/.barony`: use `tmp_path`.
- Commit messages follow the repo's style (imperative sentence, no prefix) and end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **An existing v1 journal with floor notes is opened by the new app.** Notes survive as main-floor notes and the file is upgraded in place. → Task 2, `test_v1_journal_is_upgraded`.
2. **A save caught mid-write (truncated JSON), then a good write.** The banner shows the error, the last good save stays, and both clear and refresh after the good write. → Task 4, `test_truncated_then_good_write_recovers`.
3. **Typing a note and closing the window before the 600 ms idle elapses.** The note is saved. → Task 12, `test_close_flushes_pending_note`.
4. **The followed save is deleted while an older save from another slot exists (latest mode).** The app stays on the ended run, doesn't adopt the older slot, and shows the "ended" banner. → Task 4, `test_deleted_save_does_not_fall_back_to_older_slot`.
5. **Deleting, from the runs browser, the past run currently being viewed.** The view returns to the live run with no journal errors. → Task 13, `test_deleting_viewed_past_run_returns_to_live`.

```python
class SessionController(QObject):
    about_to_change = Signal()          # emitted synchronously right before view_changed: editors flush on it
    view_changed = Signal(object)       # ViewState
    banner_changed = Signal(object)     # Banner | None
    floor_note_changed = Signal(int, int, bool)   # gamekey, dungeon_lvl, secret
    scrolls_changed = Signal(int)       # gamekey

    DEBOUNCE_MS = 300
    RETRY_MS = 1000
    MAX_RETRIES = 5

    def __init__(self, journal: Journal, settings: AppSettings, parent: QObject | None = None)
    @property
    def journal(self) -> Journal
    def start(self) -> None                       # resolve the followed save and load it
    def view(self) -> ViewState
    def banner(self) -> Banner | None
    def save_dirs(self) -> list[Path]             # [settings.save_dir] if set, else default_save_dirs()
    def saves(self) -> list[SaveSlot]             # find_saves(self.save_dirs())
    def set_save_dir(self, path: Path) -> None    # persists, re-resolves, reloads
    def follow_latest(self) -> None               # persists follow=None, reloads
    def follow_path(self, path: Path) -> None     # persists, reloads
    def reload(self) -> None                      # one load attempt; the debounce timer and tests call it
```

Behaviour to implement (the spec's "Save following and watching" section):
- **Resolve:** `follow` path if set, else `latest_save(self.save_dirs())`.
- **Latest mode never goes back:** a candidate whose `modified` is older than the last successfully loaded save's `modified` is ignored, and the current path stays followed. Track `_loaded_path` and `_loaded_mtime`. Use `datetime.fromtimestamp(path.stat().st_mtime)` for the pinned path.
- **Success:** `load_save`, then `journal.record_run(save)`. Clear the error, reset the retry count, set `ended=False`. If not in past mode, emit `about_to_change` and then `view_changed(ViewState("live", run, save, Location.of_save(save), editable=True))`. Recompute the banner.
- **`InvalidSaveError` / `FileNotFoundError`:** keep the current view. Set the banner to `Banner("error", f"Couldn't read the save: {msg}. Showing the last good data.")` for `InvalidSaveError`. Schedule a retry (`RETRY_MS`, at most `MAX_RETRIES`). When retries run out on `FileNotFoundError` with a live view on screen, set `ended=True` and re-emit the view with `ended=True, editable=True`. The banner becomes `Banner("ended", "Save no longer found: this run may have ended.")`.
- **No save resolved and nothing on screen:** `ViewState("empty")`.
- **Watching:** a `QFileSystemWatcher` on the followed file and its folder (and on every existing save dir, so new slots get noticed). Any change restarts a single-shot `DEBOUNCE_MS` timer, which calls `reload()`. Re-add the file path after each change if it's missing from `watcher.files()`.
- **Banner priority:** error > new_run > ended > past.

    def back_to_live(self) -> None
    def delete_run(self, gamekey: int) -> None    # refuses the live run (ValueError); deleting the viewed past run -> back_to_live()

Rules:
- **Past mode:** `ViewState("past", run, None, Location.of_run(run), editable=False)` with `Banner("past", "Viewing a past run.")`.
- **Save writes are refused while viewing a past run:** `save_*` / `identify_scroll` / `forget_scroll` raise `JournalError("Past runs are read-only")` when `gamekey != live_gamekey()`. The UI disables editing anyway; this is the backstop.
- **Live data keeps updating in past mode:** `reload()` keeps the latest live `SaveFile` but doesn't emit `view_changed`. If the newly loaded gamekey differs from the live gamekey held before the load, the banner becomes `Banner("new_run", "New run detected.")`.
- **`back_to_live()`** emits the stored live view straight away (or `"empty"` if there's none) and clears the `new_run` / `past` banners.
- `about_to_change` fires before every `view_changed`.
